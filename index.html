判定の基準値

計算の仕方

朝に読んだり夜に読んだりで間隔がぶれるときにON。第3段階の単価は実績がないため推定値です。

マスコット

初期状態はこのアプリ用のオリジナルキャラ「ビリすけ」です。お手持ちの画像に差し替えられます（端末内にのみ保存、外部送信なし）。
端末が「視差効果を減らす」設定のときは、最初からこちらが有効になります。

ふたりで共有する

URLと合言葉をまとめた招待コード。もう1台にはこれを貼るだけで設定が済みます。
セットアップの手順（5分・片方の端末だけで作業）
  1. console.firebase.google.com を開き、Googleアカウントでログインして「プロジェクトを作成」。名前は何でも構いません。Googleアナリティクスはオフで大丈夫です。
  2. 左メニューの 構築 → Realtime Database を開き「データベースを作成」。ロケーションは asia-southeast1。セキュリティルールはロックモードを選びます。
  3. 作成後に表示される https://…firebasedatabase.app という URL を、上の「データベースURL」に貼ります。
  4. ルールタブを開き、中身を下のルールに丸ごと差し替えて「公開」。合言葉が20文字以上のときだけ読み書きを許可する設定です。
    { "rules": { "rooms": { "$room": { ".read": "$room.length >= 20", ".write": "$room.length >= 20" } } } }
    もしこのルールが拒否されたら、下の書き方でも構いません。 <合言葉> の部分を、生成した合言葉に置き換えてください（その1部屋だけを許可する、より厳しい設定です）。
    { "rules": { "rooms": { "<合言葉>": { ".read": true, ".write": true } } } }
  5. 上の「生成」で合言葉を作り、「記録を同期する」をオンにして接続テスト。
  6. もう1台でも同じ URL と合言葉を入力し、表示名だけ変えてオンにします。これで双方向に反映されます。
このアプリのコードは公開リポジトリにありますが、URLと合言葉はコードに含まれず、各端末の中にだけ保存されます。 合言葉が鍵そのものなので、SNSなどに貼らないでください。漏れたときは新しい合言葉を生成して2台とも入れ替えてください。

同じ日付を二人が入力した場合は、あとから入力したほうが残ります。誰が入れたかは記録一覧に表示されます。 読む時刻がばらつくと日次の差分が乱れるので、どちらが読むかと、だいたいの時間帯だけは決めておくことをおすすめします。

データ

データはこの端末のブラウザ内（localStorage）だけに保存されます。機種変更やブラウザのデータ削除で消えるので、ときどきバックアップを取ってください。

このアプリについて

自宅の電気使用量が 4.2kWh/日（2025年前半）→ 8.1kWh/日（2026年6月）に倍増した原因を追うための日次記録ツール。契約はKABU&でんき（関西電力 従量電灯A 相当）。

効果判定は必ず kWh/日 で行うこと。検針期間が28〜35日でバラつくうえ、2026年8〜10月分は国の支援で燃調が下がるため、金額で見ると誤認します。
